# 規格與設計（v0.1）

## 課程：遊戲工作室

學生是「小小遊戲開發者」。一款遊戲拆成三層：

| 層 | 學生要學會 | 對應的 Scratch 概念 |
|---|---|---|
| 元素 | 做出自己的角色、道具、背景、音效 | 造型、SVG、音效 |
| 玩法 | 把「怎麼玩、怎麼贏、怎麼輸」想清楚 | 企劃卡（不用程式） |
| 規則 | 讓玩法真的運作 | 分身、偵測、變數、條件、畫筆 |

教材原本參考《Scratch 3 程式輕鬆玩》第五章（忍者切水果：分身、畫筆、計分），但不受課本框架限制。

### 流程（建議 6 節，每節 40 分鐘；核心 4 節可獨立完成）

| 節 | 工序 | 學生產出 |
|---|---|---|
| 1 | 做元素：素材工坊拼出水果、炸彈、玩家 | 自己的一組素材 |
| 2 | 規劃玩法：填遊戲企劃卡，從玩法樣板挑一個改 | 一張企劃卡 |
| 3 | 核心玩法：讓東西掉下來（分身）、玩家能操作 | 能玩的雛形 |
| 4 | 規則：計分、生命、結束 | 有輸贏的遊戲 |
| 5 | 手感：刀光（畫筆）、音效、難度成長 | 好玩的遊戲 |
| 6 | 測試與發表：同學互玩、修 bug、繳交 | 完成的作品 |

玩法樣板先做 4 種：切水果、接東西、躲避、打怪。共用零件（掉落物、計分、生命）。

### 學生最容易卡住的地方（檢查站要用白話說明）

1. 分身不會執行「當綠旗被點擊」，要另外寫「當分身產生時」。
2. 忘了刪除分身，畫面越來越卡。
3. 角色專屬變數與全域變數（計分應共用，掉落速度應各自）。
4. 重複計分：切到後分身沒刪掉，每一幀都加分。
5. 畫筆落筆後忘了抬筆。
6. 計分標準：切到加分、炸彈扣分或結束、連擊、限時或三條命。

## 系統

- 左邊工序卡、右邊編輯器，同一頁，不用切換。
- 零件卡：每個步驟附積木圖。
- 即時檢查：讀取正在執行的作品狀態，用白話提醒。
- 素材工坊：拼好的 SVG 直接加進目前的角色。
- 企劃卡：存起來，老師與同學看得到，也是評分依據。
- 編輯器隱藏 Scratch 原本的選單與標誌（`menuBarHidden`），使用我們自己的介面與名稱。

## 分數（客觀、看資料）

| 項目 | 怎麼算 |
|---|---|
| 工序完成 | 每節的檢查通過 |
| 用到的概念 | 自動偵測作品有沒有分身、刪除分身、變數、條件、畫筆 |
| 企劃完整度 | 企劃卡填完幾格 |
| 同學評價 | 發表節的互玩星星 |
| 老師加分 | 老師手動給 |

## 後臺

- 匯入班級名單 PDF；學生從下拉選單選名字，輸入學號驗證（不另設驗證碼）。
- 一位系統管理員發教師帳號；每位老師管理自己的班級與學生。
- 老師可看每位學生的企劃卡、作品（可直接試玩）、進度與分數。

## 技術

- 前端：靜態頁面 + 嵌入的 Scratch 編輯器（上游固定版本，不修改）。
- 部署：Vercel（連接 GitHub，自動部署）。
- 資料庫：Neon Postgres（經由 Vercel 整合）。作品檔（.sb3）存放方式待定。
- 編輯器預設從 Scratch 官方素材伺服器載入角色與音效庫；學校網路可能連不到，授權也需另外確認。計畫只放需要的一小批素材在自己的主機上。

## 待驗證

- 學校電腦上編輯器的載入速度。
- 作品存取（把 .sb3 存進資料庫、再載回編輯器）。
- 部署大小：目前瘦身後的編輯器約 89 MB。
