## 1. 工程交付清單（請依序做）

### P0 — 研究副本與課程流程
1. 保留「星光遊戲工作室」的 3D 場景、對話、接案背景、真實 Scratch 3 編輯器、素材工坊、老師後台；建立研究專用入口與 L1/L2/L3/L4 四個課程階段。教師可手動開關每階段與查看狀態。介入只在 L3 開啟。
2. 大幅精簡開場導覽：移除「四款遊戲都玩完才能前進」「四張客戶規格卡都完成」「共同導覽中已教授的除錯策略」等強制關卡；劇情不能阻礙實作。
3. 「接水果」統一基本任務及起始專案：左右控制籃子、一顆水果向下掉落、接到加分、落地或接到後重新由上方掉落。分身、炸彈、生命、加速變成選修，不列入必做檢查；確認主要教學能由初學者完成。
4. 統一學習目標、基本教材、Scratch 檔、時間、任務與提示取得機會。不同模式不得附帶更好看的遊戲、更多上課時間或額外答案。

### P1 — 兩種除錯介面（唯一教學變因）
實作 `S`（策略鷹架）與 `G`（一般練習）兩種顯示模式，**兩組載入同一個研究者提供的故障程式與題目**：
- `S`：依序呈現 **觀察症狀 → 推測原因 → 檢查對象 → 修改與測試 → 驗證結果** 的操作卡、回填欄位及提示層級；不得直接給答案。
- `G`：提供同等操作機會、相同故障專案、一般中性操作說明及重試機制；**不呈現五步策略鷹架**。
- 教師可以從管理介面查看配置；學生登入後只能看自己的模式。**正式前測、後測、遷移測驗無 S/G 策略提示且兩組畫面相同**。
- 製作可設定的提示文案／策略設定檔，研究者定稿前不擅自更改教學法。

### P2 — 施測平台（先做引擎，不做研究決策）
1. 建置 `assessment_registry` 與權限保護的題庫匯入：支援學生問卷（Likert／單選）、一般成就測驗（單選／含圖片）、Scratch 實作除錯（載入 .sb3／試跑／保存修改）、獨立遷移題。
2. 支援完整原版量表或研究者核定的繁體中文版本，**不擅自節選、翻譯或重排原題**；題庫、正解與授權狀態由研究者提供。題庫尚未交付時，只使用虛構的測試題驗收 UI。
3. 實作題本 `Form A`／`Form B` 與 `AB`／`BA` 順序設定，時間窗、題目顯示、計時、作答保存、交卷鎖定；研究者從安全管理介面匯入已核定的 `study_id,class_id,condition,form_order` 配置表。**Claude 不負責決定誰分哪組**。
4. 除錯評分引擎預留欄位：定位、原因、修正、驗證等分項分數，可由教師盲評覆核；不可將「有某種積木」直接當成理解能力或研究效度證據。
5. 前測、後測與問卷在程式層面分離教學提示，不能由未登入的瀏覽器、共享連結、API 回應提早取得下一題／正解。

### P3 — 安全資料儲存與研究後台
- 學生記錄以匿名 `study_id` 為主鍵，個人資訊對照表由教師權限隔離保存（或完全不儲存在研究副本）。禁止用姓名或學號組公開作品連結。
- 事件紀錄：`stage_entered`, `task_opened`, `project_run`, `block_selected`, `edit_applied`, `hint_requested`, `verification_run`, `assessment_submitted`，均含精確時間、`study_id`、`task_id`、`condition`，並能確認資料寫入成功。
- 保留關鍵 Scratch .sb3 版本（介入前／修改後／最終），不可只留覆蓋後最新版本；支援中斷續作、重新登入及跨電腦恢復。
- 研究資料與專案檔儲存採**存取授權檢查**，不可依賴「公開網址很難猜」。提供刪除研究資料的管理功能與存取紀錄。
- 教師後台匯出匿名化 CSV／ZIP：`assignments`, `events`, `responses`, `scores`, `project_versions`, `data_dictionary`。可以依班級、日期、組別篩選；需避免把真實學生資料放測試截圖。
